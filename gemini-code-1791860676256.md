# implementation_plan.md

## 1. System Architecture & High-Level Design

Aplikasi ini menggunakan paradigma **Offline-First / Local-First**. Semua mutasi berkas dan pencatatan metadata dilakukan langsung ke penyimpanan lokal dan database SQLite klien tanpa bergantung pada koneksi internet. Proses sinkronisasi ke server (Node.js/PostgreSQL) dan Google Drive API berjalan asinkron melalui antrean di latar belakang (*background sync worker*).

```
+-------------------------------------------------------------------------+
|                        FLUTTER CLIENT (DESKTOP & MOBILE)                 |
|                                                                         |
|  +--------------------+   +-----------------------+   +---------------+ |
|  | Modern UI / UX     |   | Drift ORM + SQLite    |   | Local Storage | |
|  | - 3-Pane (Desktop) |<->| - Metadata Tables     |<->| Manager       | |
|  | - Adaptive (Mobile)|   | - FTS5 Virtual Search |   | (Custom Path) | |
|  | - Command Palette  |   +-----------------------+   +---------------+ |
|  +--------------------+               ^                       ^         |
+---------------------------------------|-----------------------|---------+
                                        | Sync Queue            | Resumable
                                        v Worker                | Upload
                 +----------------------+--------------------+  |
                 |                                           |  |
                 v                                           v  v
+----------------------------------+     +-------------------------------+
|         BACKEND NODE.JS          |     |     GOOGLE DRIVE API (v3)     |
| - Express / NestJS (TypeScript)  |     | - Direct client upload via    |
| - PostgreSQL (Metadata & FTS)    |     |   OAuth 2.0 PKCE              |
| - Sync Reconciliation Engine     |     | - Resumable Upload Protocol   |
+----------------------------------+     +-------------------------------+
```

## 2. Technology Stack & Dependencies

### Client (Flutter Multiplatform)
* **Target OS:** Windows, macOS, Android, iOS.
* **State Management:** `flutter_riverpod` (v2.x) dengan code generation.
* **Database Lokal:** `drift` + `sqlite3_flutter_libs` (didukung ekstensi SQLite FTS5).
* **Storage & File Picker:** `file_picker`, `path_provider`, `path`.
* **Keamanan Kredensial:** `flutter_secure_storage`.
* **Google Integration:** `google_sign_in`, `googleapis` (Drive v3 API).
* **Networking:** `dio` (mendukung interceptor, background progress, dan chunked upload).
* **UI Components:** `lucide_icons`, `flutter_pdfview` / `pdfrx`.

### Backend (Node.js)
* **Runtime & Framework:** Node.js (LTS), TypeScript, NestJS (atau Express + Zod).
* **Database & ORM:** PostgreSQL 16+ dengan `Prisma` atau `Drizzle ORM`.
* **Auth & Security:** JWT (`@nestjs/jwt`), `bcrypt`, `helmet`, `cors`, rate-limiting.

## 3. Implementation Phases

### Phase 1: Local Storage Engine & Drift Database

**Tujuan:** Fondasi offline-first. Berkas fisik tersimpan di direktori kustom lokal dan metadata terindeks pada SQLite lokal dengan dukungan pencarian teks penuh (FTS5).

#### Task 1.1: File Storage Manager & Custom Location
* Buat service `LocalStorageService` untuk mengelola konfigurasi direktori kerja.
* **Desktop:** Simpan path absolut yang dipilih user via `FilePicker.platform.getDirectoryPath()`.
* **Android/iOS:** Tangani restriksi Scoped Storage. Simpan bookmark / persisten URI menggunakan Storage Access Framework (SAF) untuk Android dan Dokumen Terbuka Sandbox untuk iOS.
* Terapkan konvensi penamaan berkas otomatis saat disalin:
  `[ISO_DATE]_[SANITIZED_TITLE]_[UUID_SHORT].[EXTENSION]`
* Hitung hash SHA-256 setiap berkas untuk validasi integritas data saat sinkronisasi.

#### Task 1.2: Drift ORM Schema & FTS5 Setup
Buat definisi tabel pada Drift:

```dart
// lib/core/database/local_database.dart
import 'package:drift/drift.dart';

class LocalDocuments extends Table {
  TextColumn get id => text()(); // UUID v4
  TextColumn get title => text().withLength(min: 1, max: 255)();
  TextColumn get documentNumber => text().nullable()();
  TextColumn get category => text()(); // SK, Laporan, Notula, Teknis
  DateTimeColumn get documentDate => dateTime()();
  IntColumn get fiscalYear => integer()();
  TextColumn get localFilePath => text()();
  TextColumn get fileName => text()();
  IntColumn get fileSizeBytes => integer()();
  TextColumn get mimeType => text()();
  TextColumn get sha256Hash => text()();
  TextColumn get extractedText => text().nullable()();
  
  // Status: local_only, queued, syncing, synced, error
  TextColumn get syncStatus => text().withDefault(const Constant('local_only'))();
  TextColumn get gdriveFileId => text().nullable()();
  TextColumn get remoteBackendId => text().nullable()();
  
  DateTimeColumn get createdAt => dateTime().withDefault(currentDateAndTime)();
  DateTimeColumn get updatedAt => dateTime().withDefault(currentDateAndTime)();

  @override
  Set<Column> get primaryKey => {id};
}

// Virtual Table untuk SQLite FTS5
@UseRowClass(LocalDocumentFtsData)
class LocalDocumentsFts extends Table {
  TextColumn get title => text()();
  TextColumn get documentNumber => text()();
  TextColumn get category => text()();
  TextColumn get extractedText => text()();
}
```

* Konfigurasikan trigger SQLite agar tabel FTS5 terisi dan terbarui secara otomatis setiap kali ada mutasi record pada `LocalDocuments`.

### Phase 2: Modern Adaptive UI/UX & Command Center

**Tujuan:** Memberikan antarmuka adaptif yang responsif untuk desktop dan mobile dengan navigasi instan.

#### Task 2.1: Layout Architecture (Adaptive Responsive)
* **Desktop (Breakpoint $\ge$ 1024px) — 3-Pane Pattern:**
  * **Sidebar (Left):** Navigasi folder kustom, filter tahun anggaran, filter kategori dokumen, indikator kapasitas storage, dan tombol *Bulk Sync*.
  * **Document List (Center):** Virtualized list berkas dengan badge status visual, quick sort, search bar, dan drag-and-drop area untuk memasukkan berkas baru dari sistem operasi.
  * **Detail & Preview Panel (Right):** Previewer instan (PDF viewer / Image viewer / Text preview), ringkasan metadata, dan riwayat sinkronisasi.
* **Mobile (Breakpoint $<$ 1024px) — Single-View with Adaptive Sheets:**
  * Master document list dengan search bar tersemat di bagian atas.
  * *Bottom Sheet Drawer* untuk filter kategori dan detail dokumen.

#### Task 2.2: Visual Status Badges (Glanceable Indicators)
Tampilkan indikator status di samping judul berkas:
* 🟢 **Synced (Cloud):** Berkas terunggah ke Google Drive dan server.
* 🟡 **Local Only:** Berkas tersimpan lokal dan belum dijadwalkan sync.
* 🔵 **Queued / Syncing:** Berkas sedang dalam proses upload (tampilkan progress bar).
* 🔴 **Sync Failed:** Gagal upload (tampilkan tooltip alasan gagal dan tombol *Retry*).

#### Task 2.3: Command Palette (`Ctrl + K` / `Cmd + K`)
* Sediakan shortcut global keyboard listener untuk memunculkan modal *Command Palette*.
* Memungkinkan pencarian instan via kueri FTS5:
  * Filter berdasarkan nama: `nama:laporan`
  * Filter berdasarkan tahun: `tahun:2026`
  * Navigasi cepat: `> Upload Semua Berkas`, `> Ganti Direktori Lokal`.

### Phase 3: Backend Metadata Service (Node.js + PostgreSQL)

**Tujuan:** Menyediakan API terpusat untuk menyimpan metadata dokumen dinas, memvalidasi integritas data, dan menangani multi-user indexing.

#### Task 3.1: PostgreSQL Schema Migration
```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

CREATE TABLE document_categories (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    code VARCHAR(50) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL
);

CREATE TABLE documents (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    client_local_id VARCHAR(64) UNIQUE NOT NULL,
    title VARCHAR(255) NOT NULL,
    document_number VARCHAR(100),
    category_id UUID REFERENCES document_categories(id),
    document_date DATE NOT NULL,
    fiscal_year INT NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_size_bytes BIGINT NOT NULL,
    mime_type VARCHAR(100) NOT NULL,
    sha256_hash VARCHAR(64) NOT NULL,
    gdrive_file_id VARCHAR(255),
    custom_metadata JSONB DEFAULT '{}',
    search_vector TSVECTOR,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_docs_search ON documents USING GIN(search_vector);
CREATE INDEX idx_docs_hash ON documents(sha256_hash);
CREATE INDEX idx_docs_client_id ON documents(client_local_id);
```

#### Task 3.2: RESTful Batch Sync API Endpoints
* `POST /api/v1/sync/batch-metadata`:
  * Menerima array metadata berkas dari klien (`List<DocumentSyncPayload>`).
  * Validasi idempotensi: jika `client_local_id` atau `sha256_hash` sudah ada, jalankan operasi update data (Upsert).
* `POST /api/v1/sync/reconcile`:
  * Menerima daftar ID lokal dan hash untuk memverifikasi dokumen mana saja yang belum tersimpan di PostgreSQL.
* `GET /api/v1/documents/search`:
  * Pencarian berbasis `tsvector` untuk pencarian global server-side.

### Phase 4: Sync Queue Engine & Google Drive v3 Integration

**Tujuan:** Mengatur pipeline upload berkas ke Google Drive dan sinkronisasi metadata ke backend tanpa memblokir thread antarmuka (UI).

#### Task 4.1: Direct Google Drive Integration (OAuth 2.0 PKCE)
* Konfigurasikan integrasi OAuth2 pada Flutter menggunakan skema PKCE.
* Request scope terbatas: `https://www.googleapis.com/auth/drive.file` (hanya dapat mengakses berkas yang dibuat oleh aplikasi ini, mencegah akses berlebih ke file pribadi pengguna).
* Simpan refresh token dan access token terenkripsi di `flutter_secure_storage`.
* Gunakan Google Drive **Resumable Upload Protocol** untuk file berukuran $>$ 5MB agar upload yang terputus koneksi dapat dilanjutkan otomatis.

#### Task 4.2: Background Sync Worker & State Machine
Implementasikan `SyncQueueService` di Flutter:

```
[Local Document]
       |
       +--> User memilih "Upload" / "Bulk Upload"
       |
       v
   [QUEUED]
       |
       v
   [SYNCING] ---------------------------------------------+
       |                                                  |
       | 1. Upload biner ke GDrive API (Resumable)        | Jika koneksi
       | 2. Dapatkan gdrive_file_id                       | terputus/error
       | 3. Kirim metadata + gdrive_file_id ke Node.js    |
       |                                                  v
       v                                              [SYNC_FAILED]
   [SYNCED]                                               |
       |                                                  +--> Tombol Retry
       v
Update Drift DB:
syncStatus = 'synced'
gdriveFileId = res.id
```

* **Bulk Upload Mode:**
  * Proses antrean secara berurutan atau konkuen maksimal 2 berkas secara paralel untuk menjaga stabilitas I/O disk lokal dan menghindari limit rate Google Drive API.
  * Tampilkan modal progres agregat: *"Mengunggah 14 dari 50 dokumen (28%)..."*.

### Phase 5: Security Hardening & Platform Resilience

**Tujuan:** Memastikan aplikasi aman dari kerentanan direktori lokal, kebocoran token, dan kegagalan sistem berkas multiplatform.

#### Task 5.1: File Security & Path Sanitization
* Validasi dan sanitasi penamaan berkas untuk mencegah *Path Traversal Vulnerability* (`../` atau karakter ilegal di sistem operasi Windows seperti `\ / : * ? " < > |`).
* Validasi berkas berdasarkan MIME type asli melalui inspeksi *magic numbers / file header binary*, bukan semata-mata memeriksa string ekstensi.

#### Task 5.2: Token & Credential Storage
* Windows: Enkripsi kredensial memanfaatkan DPAPI (Data Protection API).
* Android: Enkripsi memanfaatkan Android Keystore.
* macOS / iOS: Enkripsi memanfaatkan Keychain Services.
* Pastikan token Google API tidak pernah dicatat pada log konsol atau file crash log.

#### Task 5.3: Offline Resilience & Edge Cases
* Tangani kondisi ketika hard disk eksternal atau flashdisk yang dijadikan *custom folder* dilepas oleh pengguna:
  * Deteksi status direktori (`await Directory(path).exists()`).
  * Jika path tidak ditemukan, ubah UI ke mode *Safe Offline Read-Only* dan tampilkan peringatan: *"Direktori penyimpanan tidak terdeteksi. Hubungkan media penyimpanan Anda."*.
* Tangani konflik data (*Conflict Resolution*): Terapkan strategi *Client-Wins* untuk draf lokal dokumen yang belum tersinkronisasi, dan berikan opsi *Duplicate with Timestamp* jika terdapat hash berkas berbeda dengan ID yang sama.

### Phase 6: Quality Assurance & Verification

**Tujuan:** Menguji seluruh alur kerja dari kondisi offline total hingga sinkronisasi penuh.

#### Task 6.1: Test Matrix
| Kasus Uji | Skenario | Hasil yang Diharapkan |
| :--- | :--- | :--- |
| **Offline CRUD** | Matikan koneksi internet, pilih berkas 50MB, simpan ke custom folder lokal. | Berkas tersalin rapi di storage lokal, Drift DB mencatat metadata, status berkas `local_only`, FTS5 dapat menemukan dokumen seketika. |
| **Direct GDrive Upload** | Nyalakan koneksi, picu upload single file ke Google Drive. | File masuk ke folder Google Drive aplikasi, `gdrive_file_id` tersimpan di Drift, status menjadi `synced`. |
| **Bulk Upload Resilience**| Putuskan jaringan saat bulk upload berjalan pada dokumen ke-5 dari 20 dokumen. | Dokumen 1-4 berstatus `synced`, dokumen 5 berstatus `error`, dokumen 6-20 tetap `queued`. Saat koneksi pulih, proses dapat di-resume tanpa mengulang dari awal. |
| **Pencarian Cepat (FTS5)** | Masukkan 1.000 record metadata dokumen, jalankan filter pencarian di Command Palette. | Hasil tampil di bawah 16ms (60 FPS tanpa UI jank). |
| **Cross-Platform Storage** | Ubah custom location ke partisi drive `D:\` di Windows dan internal storage di Android. | Berkas tersimpan di direktori yang ditentukan tanpa error permission. |
